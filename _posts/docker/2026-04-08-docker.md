# Docker를 "쓴다"에서 "운영한다"로 가는 과정

Docker를 처음 공부하면 보통 이렇게 이해한다.

> "VM보다 가볍다"

이 말 자체는 틀리지 않다.\
하지만 실무에서는 이 설명으로는 아무 문제도 해결할 수 없다.

실제 장애 상황에서는 이렇게 바뀐다.

-   왜 컨테이너 하나가 CPU를 다 먹지?
-   왜 다른 서비스까지 느려지지?
-   VM처럼 격리된 거 아니었나?

이 질문을 해결하려면 Docker를 "도구"가 아니라\
**구조와 동작 방식**으로 이해해야 한다.

------------------------------------------------------------------------

# 1. VM vs Docker (왜 중요한가)

## 문제 상황

-   컨테이너 하나가 서버 전체를 느리게 만든다
-   특정 서비스 장애가 전체로 확산된다

왜 이런 일이 발생할까?

------------------------------------------------------------------------

## 원인

Docker는 VM이 아니다.

VM: Host → Hypervisor → Guest OS → App

Docker: Host Kernel → Container → App

즉,

> 모든 컨테이너는 같은 커널을 공유한다

------------------------------------------------------------------------

## 결과

-   완전 격리가 아님
-   자원은 공유됨

------------------------------------------------------------------------

## 해결 방법

그래서 반드시 필요한 것이:

-   CPU 제한 (`--cpus`)
-   메모리 제한 (`--memory`)
-   cgroup 기반 제어

------------------------------------------------------------------------

## 실무 포인트

자원 제한을 하지 않으면:

> 컨테이너 하나가 서버 전체를 먹는다

------------------------------------------------------------------------

# 2. 컨테이너가 바로 죽는 이유

## 문제 상황

``` bash
docker run -d centos:8
```

컨테이너가 바로 종료됨

------------------------------------------------------------------------

## 원인

컨테이너는 "프로세스"다.

> PID 1이 종료되면 컨테이너도 종료된다

------------------------------------------------------------------------

## 해결

``` bash
docker run -d centos:8 tail -f /dev/null
```

------------------------------------------------------------------------

## 실무 포인트

이걸 모르면:

-   exec 접속 불가
-   테스트 환경 유지 불가
-   서비스 바로 종료

------------------------------------------------------------------------

# 3. 디버깅이 안 되는 이유

## 문제 상황

-   컨테이너는 떠 있는데 안 된다
-   이유를 모른다

------------------------------------------------------------------------

## 원인

logs만 보기 때문

------------------------------------------------------------------------

## 해결 루틴

``` bash
docker ps
docker logs
docker inspect
docker stats
```

------------------------------------------------------------------------

## 핵심

-   logs = 결과
-   inspect = 상태 (원인)

------------------------------------------------------------------------

# 4. docker inspect를 안 보면 생기는 문제

## 문제 상황

-   포트 열었는데 접속 안 됨
-   환경 변수 적용 안 됨
-   볼륨이 안 붙음

------------------------------------------------------------------------

## 해결

inspect로 실제 상태 확인

------------------------------------------------------------------------

## 예시

``` bash
docker inspect --format='{{json .NetworkSettings.Ports}}'
docker inspect --format='{{json .Config.Env}}'
docker inspect --format='{{json .Mounts}}'
```

------------------------------------------------------------------------

# 5. 네트워크가 안 되는 이유

## 문제 상황

-   컨테이너 간 통신 실패
-   서비스 연결 안 됨

------------------------------------------------------------------------

## 원인

Docker 네트워크 구조 이해 부족

------------------------------------------------------------------------

## 구조

Container ↔ veth ↔ docker0 ↔ Host

------------------------------------------------------------------------

## docker0

-   기본 bridge
-   내부 라우팅 수행

------------------------------------------------------------------------

## 해결

사용자 정의 네트워크 사용

``` bash
docker network create my-network
```

------------------------------------------------------------------------

## 핵심

> 컨테이너 이름 = DNS

------------------------------------------------------------------------

# 6. 이미지 용량이 계속 커지는 이유

## 문제 상황

-   이미지 빌드할수록 커짐
-   배포 느림

------------------------------------------------------------------------

## 원인

Docker Image Layer 구조 때문

------------------------------------------------------------------------

## 구조

-   Base
-   Install
-   Copy
-   Config

------------------------------------------------------------------------

## 해결

### 1. RUN 최소화

### 2. 캐시 제거

### 3. .dockerignore

### 4. 멀티 스테이지

------------------------------------------------------------------------

## 실무 포인트

이미지 용량 = 배포 속도 + 비용

------------------------------------------------------------------------

# 7. 운영 중 장애 대응이 안 되는 이유

## 문제 상황

-   CPU 과점
-   메모리 누수
-   컨테이너 내릴 수 없음

------------------------------------------------------------------------

## 해결

docker update 사용

``` bash
docker update --cpus 1 app
docker update --memory 512m app
```

------------------------------------------------------------------------

# 8. 성능 테스트가 의미 없는 이유

## 문제 상황

-   테스트 결과가 환경마다 다름
-   재현 안 됨

------------------------------------------------------------------------

## 원인

환경 통제가 안 됨

------------------------------------------------------------------------

## 해결

옵션 고정

``` bash
--cpus
--memory
--memory-swap
```

------------------------------------------------------------------------

## 확인

``` bash
docker stats
top
free -h
```

------------------------------------------------------------------------

# 9. 결론

Docker는 단순 실행 도구가 아니다.

> 문제를 해결하기 위한 환경 제어 도구다

이걸 이해하면:

-   장애 원인을 설명할 수 있고
-   자원을 제어할 수 있고
-   테스트 결과를 해석할 수 있다
